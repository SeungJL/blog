어바웃과 카공지도는 Next 앱 하나를 공유한다. 도메인만 둘이다 — `study-about.club` 과 `카공지도.com`(퓨니코드로 `xn--ob0b42knwutje.com`). 지난 글에서 정리한 건 앱 안쪽 레이어였다. 바깥에서 두 서비스가 어떻게 보이는지는 손대지 않은 채였다.

구글에서 카공지도를 검색하면 제목이 "어바웃: 20대 커뮤니티형 동아리"로 떴다. 파비콘도 어바웃 배지였다.

## og 태그는 이미 갈라져 있었다

`pages/_document.tsx` 는 요청 호스트를 보고 og 값을 분기하고 있었다. 카공지도 호스트로 들어오면 카공지도 제목·설명·이미지가 나간다. 카카오톡으로 링크를 공유하면 카드가 제대로 떴다.

구글은 그 태그를 보지 않는다. 검색결과 제목은 `og:title` 이 아니라 `<title>` 이다. 그리고 `<title>` 은 `pages/_app.tsx` 에 기본값 하나뿐이었다.

페이지에서 `next/head` 로 덮어쓰면 될 일로 보였지만 그 경로는 막혀 있었다. Layout 이 토큰 없는 SSR 에서는 children 을 렌더하지 않아, 페이지의 `next/head` 가 서버 HTML 에 실리지 않는다. 크롤러가 받아가는 건 그 서버 HTML 이다. 그래서 Layout 바깥인 `_app.tsx` 에서 경로로 갈랐다.

```tsx
// pages/_app.tsx
const isCafeMapRoute = (pathname: string) =>
  pathname === "/" || pathname === "/cafe-map" || pathname.startsWith("/cafe-map/");

<title>{isCafeMapRoute(router.pathname) ? CAFE_MAP_TITLE : DEFAULT_TITLE}</title>
```

`"/"` 를 카공지도로 둔 건 카공지도.com 루트 전용이기 때문이다. `about20s.club` 의 `"/"` 는 `getServerSideProps` 에서 `/home` 으로 보내 여기까지 렌더되지 않는다.

## 구글이 보는 자리와 우리가 채워둔 자리

| 검색결과 요소 | 구글이 읽는 것 | 그때 들어 있던 값 |
|---|---|---|
| 제목 | `<title>` | 어바웃 기본값 하나 |
| 스니펫 | `meta[name=description]` | 없음 (`og:description` 만 있었다) |
| 사이트 이름 | `og:site_name`, JSON-LD `WebSite.name` | `og:site_name` 에 `NEXT_PUBLIC_NEXTAUTH_URL` 값이 그대로 |
| 파비콘 | 사이트 루트의 `/favicon.ico` | `public/favicon.ico` 를 두 도메인이 공유 |

네 자리 모두 og 태그만 갈라두고 나머지는 어바웃 기본값을 쓰고 있었다. `og:site_name` 에 사이트 이름 대신 환경변수 URL 문자열이 들어가 있던 건 이때 같이 찾았다.

## `/favicon.ico` 는 태그로 막을 수 없다

`<link rel="icon">` 을 호스트별로 갈라도 파비콘은 그대로 어바웃 배지였다. 크롤러와 브라우저는 관례적으로 `/favicon.ico` 를 먼저 찾고, 그 경로에는 `public/favicon.ico` 가 있다. 정적 파일은 라우트보다 먼저 응답하므로 페이지를 만들어 가로챌 수도 없다.

`next.config.js` 의 `rewrites().beforeFiles` 가 `public/` 보다 먼저 도는 유일한 지점이었다.

```js
// next.config.js
async rewrites() {
  return {
    beforeFiles: [
      {
        source: "/favicon.ico",
        has: [{ type: "host", value: "(www\.)?xn--ob0b42knwutje\.com" }],
        destination: "/cafe-map-icon-180.png",
      },
    ],
  };
}
```

## 같은 내용이 두 주소에 있었다

`study-about.club/cafe-map` 과 `카공지도.com/` 은 같은 화면이다. canonical 을 카공지도.com 으로 통일하고, sitemap 에서는 `/cafe-map` 을 뺐다. 실어두면 canonical 과 서로 다른 말을 하는 셈이 된다.

## robots.txt와 sitemap.xml을 페이지 라우트로 만들었다

`Sitemap:` 줄은 자기 도메인을 가리켜야 한다. 정적 `public/robots.txt` 로는 호스트 분기를 할 수 없어서 `pages/robots.txt.tsx`, `pages/sitemap.xml.tsx` 로 만들고 `getServerSideProps` 에서 호스트를 봤다. 크롤러가 자주 받아가는 파일이라 `Cache-Control: public, max-age=86400` 을 붙였다.

sitemap 에는 로그인 없이 내용이 보이는 경로만 실었다 — `/home`, `/faq`, `/newbie-guide`, `/notice`. 스터디·모임·커뮤니티는 전부 로그인 뒤라서 넣어봐야 빈 페이지로 수집된다.

Search Console 인증 태그는 두 속성의 것을 같이 내보낸다. 한 앱이 두 도메인을 서빙하니 태그도 양쪽에 다 나가지만, 구글은 해당 속성의 토큰만 찾으므로 서로 간섭하지 않는다.

```tsx
<meta name="google-site-verification" content="<카공지도 토큰>" key="gsc-cafe-map" />
<meta name="google-site-verification" content="<어바웃 토큰>" key="gsc-about" />
```

호스트 분기 로직은 `constants/seo.ts` 한 파일로 모았다. `_document.tsx`, `robots.txt.tsx`, `sitemap.xml.tsx` 가 같은 판단을 세 번 하고 있었다.

## 확인하지 않은 것

색인이 실제로 갱신됐는지는 확인하지 않았다. 재크롤링 주기가 있어 배포 직후에 알 수 있는 값이 아니다. 확인할 지표는 Search Console 각 속성의 색인 현황과 검색결과에 뜨는 제목·파비콘이다.

`meta[name=description]` 은 넣었지만 구글이 이 값을 쓸지 본문에서 따로 발췌할지는 구글이 정한다.

## 결과

커밋 세 개, 파일 여덟 개. 지난 글에서 정리한 건 코드 레이어였다. 그 바깥에 `<title>` 한 줄, `/favicon.ico` 하나, `Sitemap:` 한 줄이 남아 있었다.
