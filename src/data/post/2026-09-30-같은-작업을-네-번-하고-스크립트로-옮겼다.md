카공지도의 카페 목록에는 대표 이미지가 붙는다. 크롤러가 네이버에서 첫 번째 사진을 가져오는데, 그게 로고이거나 음료 클로즈업인 경우가 많다. 주제별 추천 목록을 만들 때는 직접 고르는 편이 낫다.

콘센트 기준으로 한 번, 공부 분위기로 한 번, 인스타 감성으로 한 번, 데이트하기 좋은 곳으로 한 번. 네 번 하고 나서 스크립트로 옮겼다.

## 매번 같았던 다섯 단계

```
1. 랭킹   주제 조건으로 상위 20곳 (카공족·스터디카페 제외)
2. 수집   네이버 업체등록 사진 전량 (GraphQL 커서 페이징)
3. 선별   contact sheet로 눈 검수
4. 선택   picker 페이지를 띄워 최종 이미지를 고름
5. 저장   DB place.image 갱신 + 카페명·주소·AI평가·이미지 파일 내보내기
```

바뀌는 건 1단계의 조건 하나였다. 2~5단계는 네 번 모두 같은 일을 했고, 같은 곳에서 같은 방식으로 막혔다.

## 막혔던 자리가 곧 내용이다

스크립트로 옮길 값이 있었던 건 단계 자체가 아니라 단계마다 알아낸 것들이었다.

**동점이 매우 흔하다.** 콘센트 점수 5.0인 카페가 50곳이다. 한 기준으로 정렬하면 순서가 사실상 무작위다. `<주제 점수> desc → 총점 desc → 네이버 키워드 투표 수 desc` 로 3차까지 간다. 점수 계산식 자체는 `About/features/study/lib/studyUtils.ts` 의 `calculateTotalScore` 를 그대로 옮겨 쓴다. 여기서 다르게 계산하면 서비스 화면과 순위가 어긋난다.

**브랜드 체인은 거의 못 쓴다.** 스타벅스·투썸·이디야·할리스의 업체등록 사진은 로고와 음료와 키오스크뿐인 경우가 많다. 랭킹에는 남기되 제외할지 한 번 묻는다.

**메타데이터로는 로고를 못 거른다.** 업체등록 사진의 `title` 은 대부분 상호명이다. title 이 "○○카페"인데 실물이 로고인 경우가 흔하다. 결국 눈으로 봐야 한다.

**눈 검수는 두 번 해야 한다.** 230px 셀에서는 사진 품질을 판정할 수 없다. 1차는 230px 로 내부 컷만 남기고, 2차는 380px 로 품질을 본다. 처음에는 한 번에 끝내려다 다시 돌렸다.

## picker에서 걸린 것들

고를 사진을 웹 페이지로 띄워 직접 선택하게 하는 단계다. 여기서 걸린 건 전부 아티팩트 쪽 제약이었다.

- 네이버 이미지 URL 은 CSP 에 막힌다. 이미지를 내려받아 페이지 파일로 같이 올려야 한다
- publish 한 번에 파일 255개 제한. 넘으면 나눠 올린다
- 갱신할 때는 같은 파일 경로로 다시 올려야 URL 과 저장된 선택이 유지된다. 후보 배열 순서가 바뀌면 저장된 `index` 가 어긋나므로 원본 URL 로 매칭해 재매핑한다

마지막 항목은 실제로 틀린 적이 있어서 규칙이 됐다. 후보를 추가하고 다시 올렸더니 이전 선택이 다른 사진을 가리켰다.

## 저장은 미리보기를 먼저

DB 를 건드리는 마지막 단계는 `APPLY=false` 로 먼저 보여주고 확인받은 뒤 `APPLY=true` 로 실행한다. 미리보기에서 걸러진 것 중 하나가 해상도였다 — 요구치보다 작은 이미지는 업스케일하지 않고 목록으로 보고한다. 네이버 원본이 그 크기다. 데이트 카페 8곳 중 한 곳이 여기 걸려 다른 사진으로 바꿨다.

## 결과

`SKILL.md` 하나와 스크립트 일곱 개(`rank` / `pull-photos` / `sheets` / `build-picker` / `apply` / `setup` / 공용 `lib`), picker 템플릿 하나. 인스타 감성 26곳과 데이트 8곳은 이 경로로 DB 에 반영했다.

전에 한 번, 같은 지적을 두 번 하지 않으려고 규칙을 파일에 적어두는 이야기를 썼다. 그건 문장이었고 이번 건 실행되는 파일이다. 차이는 규칙이 지켜지는지를 사람이 확인하지 않아도 된다는 것이다. 다만 3단계는 여전히 눈으로 본다. 로고인지 아닌지는 아직 코드로 못 가른다.
